## ROTA API repair
The 60-second client timer is scoped to the active MCRO view and pauses while the document is hidden. ROTATION flashes only when the authoritative SQLite file version plus table-row signature changes; initial and identical responses do not flash. The API now reports one `factor_momentum_global` table, calculated as the average of the CN, US, and EU factor-momentum tables, plus the three regional beta and three regional Spearman tables. The empty `xsec_mean_beta_us` root cause was invalid/singular OLS systems being allowed through `solveK`; the C++ solver now rejects non-finite or singular matrices and averages only finite valid fits. Verification: local `/api/rotation` returned seven tables, 500 global factor rows, and 500 non-null US beta rows.

## ROTARAW Yahoo migration
ROTARAW uses the supplied dumb_china_factor universe, the supplied EU ETF universe, and the requested SOXX addition. Yahoo Finance chart daily closes are the primary source; there are no synthetic or hard-coded market values. Each ticker is fetched with a bounded four-worker pool and written serially to `app/rotation/rota_raw.db` with `(ticker,date)` uniqueness and a terminal `complete` or `unavailable` status. The initial run completed 56 tickers and 27,561 daily rows, with coverage through 2026-10-26 for the known symbols. The read model exposes normalised performance and return-correlation views for 7D, 14D, 30D, 60D, 90D, and 252D selections. The existing 60-second MCRO refresh remains the delivery loop; ROTARAW flashes only when the persisted raw-cache version changes. A recurring ScheduleTask is active for 16:00 Asia/Shanghai daily refreshes.

## FXECON Freox patch migration

The supplied `freox_all_v5.patch` targets a separate Streamlit application, so it was not applied as a replacement. Its HOPE taxonomy and FX ladder were migrated into `app/ficc/econ.py` behind BYOT's existing authenticated server and MCRO tab router. Yahoo Finance is attempted first through the QuantPilot `YahooProvider` chart adapter: 1-minute bars for fast returns and 2-year daily bars for 5D/14D/1W/63D/253D returns. The initial live run returned 21 currencies, 20 minute feeds, 9,538 minute ticks, and 10,843 daily rows in `app/ficc/fx_econ.db` in 19.1 seconds. The keyless open.er-api source is used only when Yahoo has no usable result; no stale or fabricated values are served. The UI reports provider, freshness, source per row, and an unavailable state. FXECON uses the existing MCRO 60-second refresh loop and flashes only when the authoritative row-value signature changes.

## HOME HOPE calendar

The supplied patch and `HelloThereMatey/tedata` repository were inspected at commit `34f28c5161257960148f3f543c021e0aaac617fd`. `tedata` is a Selenium/BeautifulSoup time-series scraper, not a calendar store, so its context was migrated at the existing BYOT provider boundary rather than added to the request path as a browser automation dependency. The HOME adapter fetches `https://tradingeconomics.com/calendar` with the provider's timezone cookie set to Asia/Shanghai (+480), parses stable row attributes, converts the displayed local event time to an explicit UTC `event_at`, and persists rows in `app/ficc/fx_econ.db` before serving them. The verified snapshot contained 166 events across all seven requested categories: firing, unemployment, hiring, housing, pmi, ppi, and cpi. FXECON no longer displays the HOPE rail or the `24 monitored countries` text. HOME uses the existing 60-second MCRO polling loop; the Trading Economics source is bounded to a 30-minute cache TTL and retains an unavailable state on fetch failure.

## MCRO date and correlation repair

The published ROTATION table date was not hard-coded in the browser: it came from the latest committed `FF_Rotation.cpp` SQLite output, whose current `spearman_rho` and factor-momentum maximum date is `2026-10-23`. The bounded fix now exposes that authoritative source date separately from a dynamic browser/server TODAY date, so stale source data is visible rather than relabelled. Three derived `pearson_rho_cn`, `pearson_rho_us`, and `pearson_rho_eu` tables are computed from each ticker's six Spearman factor values versus the six same-region factor returns for lookbacks 28, 62, 128, and 256 days. ROTACHRTS uses those per-ticker Pearson values on its Y axis while retaining Spearman Rho on X.

ROTARAW now shows its latest persisted Yahoo close date as Y-M-D, removes the Trading Date caption and right-edge labels, and places a wrapped ticker legend beneath the plot. FXECON now shows Y-M-D without the requested provider/status text or SOURCE column. HOME no longer exposes the Trading Economics URL/freshness text and uses HOME for its visible calendar labels.
